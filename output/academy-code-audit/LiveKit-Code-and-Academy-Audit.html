Four contained defects repaired

AC-CODE-01 · FIXED · MEDIUM

P2 could not retry a failed native SDK close

projects/channel-continuity/python/src/channel_continuity/native.py:295

Before. The runtime kept its failed close task forever. An SDK close failure left the resource owned, but every later public aclose only rethrew that old failure; its own test repaired a private field.

After. Pending and successful close attempts remain shared. A definitively failed/cancelled attempt permits one later public retry. Admission remains fenced, independent work drains, and observer cancellation does not abandon actual cleanup.

Genuine pinned-SDK regression failed before the fix; 18 native SDK tests passed after, including concurrent retries and a cancelled close waiter.

AC-CODE-02 · FIXED · MEDIUM

P3 could remain stuck after definite pre-acceptance capacity rejection

projects/delegation-reliability/python/src/delegation_reliability/native_policy.py:523

Before. The attempted flag was set before submit. A definite capacity rejection could leave all future calls inspecting work that had never been accepted.

After. Only initial-submit capacity restores explicit retry of the same frozen request. Unknown acceptance and any post-acceptance runner failure remain lookup-only; no new work identity or hidden retry is introduced.

18 policy tests and 3 genuine SDK tests pass. New negatives distinguish unknown submit ACK and capacity after acceptance. The authority/specialist in this focused schedule are in-memory fixtures, not PostgreSQL.

AC-CODE-03 · FIXED · MEDIUM

Older P1 diagnostic failures could replace operation truth

projects/agent-continuity/python/src/continuity_lab/managed_inquiry_worker.py:42

Before. A logger could raise after finish_success, causing a successful public worker call to report failure. A hostile diagnostic code getter could replace the original exception. Eight older logging helpers shared the escape pattern.

After. Ordinary telemetry exceptions are contained in those helpers; managed and legacy inquiry error-code extraction is protected. Fatal BaseException control flow remains unsuppressed. No schema, transaction, consent or retry rule changed.

Four regression methods were observed failing before their corresponding fixes. All 19 inquiry-worker tests pass, including eight logger outage cases, fatal propagation and preserved public results/errors.

AC-CODE-04 · FIXED · MEDIUM

Provider instructions invented running work from a noncurrent result

services/channel_policy_demo/native_provider_models.py:52

Before. The prompt told the model that no_delivery, not_applicable and unavailable all meant the policy check was still running. Those states can instead reflect a completed stale result or a failed read.

After. The prompt asks for a neutral no-current-answer response and explicitly says those states do not establish whether work is running. Current-result facts and exact action authority remain separate.

Existing 13 offline provider-mode tests pass. This verifies composition/wire contracts, not whether a live model consistently follows the revised instruction; actual provider/media qualification was not rerun.
