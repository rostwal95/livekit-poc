## Behavior and scope

The goal is to complete implementation task P1-I28 with an explicit, fully local
real-inference profile (`local_real`). Preserve the scripted profile and its
existing budgets. The user-approved target is a local proof of concept (POC).
GitHub publishing and remote continuous integration (CI) are outside scope.

The profile uses the following, with no scripted transcript or response mapping:

- actual Whisper automatic speech recognition (ASR);
- a local Qwen model through the native LiveKit large language model (LLM)
  plugin interface;
- speech generated by Piper text-to-speech (TTS).

## Interfaces and ownership

### Models and engines

| Limit | Value |
| --- | --- |
| Model pins | Ten exact byte sizes and digests in `local-setup/models` |
| Total model files | 2,708,795,741 bytes, including the 859-byte Ollama manifest, under a 4 GiB declaration |
| Explicit model preparation | Hard 1800-second child/supervisor deadline |

Model preparation terminates, kills and reaps its owned child before releasing its
file lock. Normal verification and runtime never download models. Public model
files are readable by the unprivileged engine user ID (UID); credentials remain
private.

The separately bounded local engines and the application's pinned libraries are:

| Requirement | Version or value | Notes |
| --- | --- | --- |
| Ollama | 0.40.15 | Local engine with Qwen3:4b-instruct |
| whisper.cpp | 1.9.5 | Local engine with base.en |
| Piper | 1.8.0 | Local engine with LJSpeech; the Piper process is separate from the agent |
| LiveKit OpenAI plugin | 1.8.11 | The only root application addition; compatible pinned version |
| OpenAI | 3.46.0 | Existing frozen version |
| httpx2 | 2.16.0 | Existing frozen version |

Retain the model and engine licenses and the voice card. Existing external
versions must not silently change.

### Native providers and media bounds

Each native provider owns:

- one active and one waiting HTTP operation;
- fixed private service endpoints;
- bounded streamed response bytes;
- independently closed resources.

The actual wire transport clears ambient OpenAI headers and proxies. Local dummy
credentials cannot become remote provider authority.

| Limit | Value |
| --- | --- |
| Audio | 16-bit PCM (PCM16), mono, 16 kHz; at most 12 s per turn |
| Generated TTS | PCM16, mono, 22050 Hz; at most 20 s per response |
| Real speech-to-text (STT) and TTS | 10 s native budget each, around an 8 s engine child |
| LLM | 30 s, 128 output tokens, 256 chunks, 4 KiB output and 64 KiB context; no arbitrary tool arguments |

Manual-flush STT is a supported streaming extension with `vad=None` (no voice
activity detection). Batch STT is not silently swapped into an incompatible
software development kit (SDK) node.

### Mode binding and browser budgets

The authenticated session response and the native readiness attribute bind the
fixed mode, `scripted` or `local_real`. UI and trace/usage evidence must label the
actual mode. Real commit acknowledgement has its own 12 s browser budget. The
scripted 8 s budget, the 8 s budget for all other remote procedure calls (RPCs)
and the 5 s media cleanup budget remain unchanged. Exact consent, original
identities, private credentials, source ownership and durable execution semantics
remain.

## Failure cases and validation

A missing cache, engine or dependency, or missing required inference, is
non-passing. Reject:

- unknown configuration, model or schema;
- unsafe cache or redirect paths;
- duplicate fields;
- invalid, silent or truncated speech;
- excessive bytes, tokens, chunks or tasks;
- unsupported media;
- unsafe function calls;
- unverified mode or readiness.

Keep private captured model and process output ephemeral. Retain only fixed codes,
numeric counters, limits, timestamps and identity hashes. Do not retain prompts,
transcripts, audio bodies, request metadata, environment values or exception
chains. Keep cancellation and cleanup facts separate from uncertain business
facts. Model output grants no permission.

Gate names starting with G- refer to the engineering gates in the
[validation plan](../validation-plan.md). G-MODEL and G-LOCAL-POC are specific to
this work item.
